## 1 · La composición: rejilla de 12 columnas

El problema a resolver: tres de las cuatro tarjetas elegidas son compactas, así que apiladas a ancho
completo dejan **medio ancho vacío en cada fila** y obligan a un scroll que no enseña nada.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ ‹ Tierlist del grupo                                                     │
├──────────────────────────────────────────────────────────────────────────┤
│  CABECERA · splash panorámico                                    12/12   │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  │
│  12 partidas │ 58% 7V-5D │ 30% presencia │ 3.42 KDA                      │
├────────────────────────┬────────────────────────┬────────────────────────┤
│ FASE TEMPRANA Y MACRO  │ ESPECIALISTAS          │ SINERGIAS Y RIVALES    │
│   4/12                 │   4/12                 │   4/12                 │
│  oro@14    CS/min      │ N1ght  ▓▓▓▓▓▓▓▓░ 83%   │ CON    (◎)(◎)(◎)(◎)    │
│  1.ª sangre 1.ª torre  │ Kaori  ▓▓▓▓▓░░░░ 50%   │ CONTRA (◎)(◎)(◎)(◎)    │
│                        │ Turbo  ░░░░░░░░░  0%   │                        │
├────────────────────────┴────────────────────────┼────────────────────────┤
│ OBJETOS Y RUNAS                          8/12   │ HABILIDADES     4/12   │
│  [o][o][o][o][o][o]                             │   [Q] › [W] › [E]      │
│  (◉)(●)(●)(●) │ (●)(●) │ ● ● ●                  │   R en 6, 11 y 16      │
└─────────────────────────────────────────────────┴────────────────────────┘
```

**La rejilla:**

```scss
.cf-page {                      // el contenedor de la ficha
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  gap: var(--sp-4);
  align-items: stretch;         // sin esto quedan huecos bajo la tarjeta más baja
  max-width: var(--container);
  margin-inline: auto;
}

.cf-card--cabecera  { grid-column: span 12; }
.cf-card--macro     { grid-column: span 4; }
.cf-card--espec     { grid-column: span 4; }
.cf-card--duos      { grid-column: span 4; }
.cf-card--builds    { grid-column: span 8; }
.cf-card--skills    { grid-column: span 4; }
```

**«No deben quedar espacios vacíos» son dos reglas, no una:**

1. **Entre tarjetas de la misma fila**, lo resuelve `align-items: stretch`: todas miden lo que la más
   alta.
2. **Dentro de una tarjeta estirada**, lo resuelve el reparto interno. Cada tarjeta es
   `display: flex; flex-direction: column;`, su cabecera va arriba y **su contenido lleva
   `flex: 1` con `justify-content: space-around`**, así que si la tarjeta crece, su contenido se
   reparte el alto sobrante en vez de amontonarse arriba y dejar un hueco abajo.

**Al estrechar** (los escalones están en `src/styles/_breakpoints.scss`, con `@use 'breakpoints' as *;`):

| Ancho | Rejilla |
|---|---|
| ≥ 860px | la de arriba: 12 · 4+4+4 · 8+4 |
| `$bp-compact` (860px) | dos columnas: cabecera 12; macro 6 + especialistas 6; sinergias 6 + habilidades 6; objetos y runas 12 |
| `$bp-mobile` (760px) | una columna: todo `span 12` |

## 2 · Runas sin texto

En `tplBuilds4`, **fuera todo el texto de las runas**: los nombres debajo de los iconos y cualquier
etiqueta de fila o de árbol. Quedan **solo las imágenes**, en una tira:

```text
 [◉ 48]  [● 32] [● 32] [● 32]   │   [● 32] [● 32]   │   [● 20] [● 20] [● 20]
 angular    las tres primarias      las dos secundarias     los tres fragmentos
```

- Los separadores `│` son un `border-left: 1px solid var(--nf-border)` con `padding-inline`, no un
  carácter.
- El nombre de cada runa sobrevive en el **`alt` y el `title`** de la imagen, que es donde no
  estorba.
- **Se conserva una sola línea de texto en la tarjeta**, debajo de todo, en `--fs-caption`
  `--nf-text-dim`: `En 7 de 12 partidas · 57% de victorias`. Sin ella la tira de runas es decoración;
  con ella es un dato. Si el usuario la quiere fuera también, lo dirá.
- Los objetos **sí conservan** su porcentaje debajo de cada icono, como están.

## 3 · Especialistas del grupo: barras con burbujas

Se rehace `tplEspecialistas` entero. Deja de ser una lista de cifras y pasa a **una barra por
jugador**, porque la pregunta que responde la tarjeta —quién domina a este campeón— se lee mejor
comparando longitudes que leyendo tres porcentajes.

```text
┌──────────────────────────────────────────┐
│ ESPECIALISTAS DEL GRUPO                  │
│ (av) N1ght                    5V-1D  83% │
│      ▓▓▓▓▓▓ ᵒ ▓▓ ᵒ ▓▓▓▓▓▓ ᵒ ▓▓░░░░░░░░░ │
│      KDA 4.10 · 6 partidas               │
│ (av) Kaori                    2V-2D  50% │
│      ▓▓▓ ᵒ ▓▓▓▓▓ ᵒ ▓▓░░░░░░░░░░░░░░░░░░ │
│      KDA 2.85 · 4 partidas               │
└──────────────────────────────────────────┘
```

**Cada fila:**

- Arriba: `nf-avatar` de 28px (`[fallback]` al nombre, sin `src`), el nombre en `--fs-body`, y a la
  derecha el récord y el winrate en `nf-mono`; el winrate en `--fs-h3`, en `--nf-success` si ≥ 50 y
  en `--nf-danger` si no.
- En medio: la barra.
- Abajo: `KDA 4.10 · 6 partidas` en `--fs-caption` `--nf-text-dim`.

**La barra:**

- Carril `height: 16px`, `border-radius: var(--nf-radius-sm)`, `background: var(--nf-surface-3)`,
  `overflow: hidden`. Dieciséis píxeles y no ocho: las burbujas tienen que verse, y en una barra fina
  no se ven.
- Relleno con `width` igual al winrate, `overflow: hidden` y `position: relative`, en
  `--nf-success` (o `--nf-danger` por debajo de 50). Con winrate 0 el relleno mide 0 y **no se pinta
  ninguna burbuja**: es el caso de Turbo, y hay que comprobarlo.

**Las burbujas** —el efecto que pidió el usuario, y que tiene que verse claramente:

- Dentro del relleno van **seis `<span class="cf-bubble">`**. Como el relleno lleva
  `overflow: hidden`, las burbujas **nacen al principio de la barra y mueren justo donde termina el
  relleno**, que es exactamente lo pedido.
- Cada una: `position: absolute`, `border-radius: 50%`,
  `background: rgba(255, 255, 255, 0.55)`, `box-shadow: 0 0 6px rgba(255,255,255,.35)`.
- Tamaños y posiciones escalonados, con `--i` del 1 al 6 puesto desde la plantilla:
  diámetros `5px, 7px, 4px, 8px, 6px, 5px`; `bottom` entre `1px` y `7px`.
- Animación: recorren el relleno de izquierda a derecha mientras suben un poco y se desvanecen.

```scss
@keyframes cf-burbuja {
  0%   { transform: translate(0, 0) scale(0.6); opacity: 0; }
  12%  { opacity: 0.95; }
  70%  { opacity: 0.75; }
  100% { transform: translate(var(--cf-recorrido, 320px), -7px) scale(1); opacity: 0; }
}

.cf-bubble {
  animation: cf-burbuja var(--cf-dur, 3s) linear infinite;
  animation-delay: var(--cf-delay, 0s);
}
```

- `--cf-recorrido: 100%` no sirve en un `translate` horizontal fiable dentro de un contenedor de
  ancho porcentual: usa **`left: 0` y `translate` en píxeles con `--cf-recorrido: 340px`** y deja que
  el `overflow: hidden` del relleno recorte lo que sobre. El efecto es el mismo y no depende de medir
  nada en JavaScript.
- Duraciones escalonadas entre `2.4s` y `4.2s` y retardos entre `0s` y `2.2s`, para que no suban en
  formación.

**Obligatorio, y no es opcional:**

```scss
@media (prefers-reduced-motion: reduce) {
  .cf-bubble { animation: none; opacity: 0.5; }
}
```

Una animación infinita sin esta salida es un problema de accesibilidad de manual, y aquí cuesta tres
líneas.

## 4 · Hover en todo

Un **lenguaje único**, no un efecto distinto por bloque. Todo con
`transition: <prop> var(--nf-dur-fast) var(--nf-ease-out);`.

| Qué | Al pasar el puntero |
|---|---|
| **Cualquier tarjeta** (`.cf-card`) | `transform: translateY(-2px)`, `border-color: var(--nf-border-strong)`, `box-shadow: var(--nf-shadow-pop)` |
| **Icono de campeón** (rejilla de sinergias) | `transform: scale(1.08)` y `box-shadow: 0 0 0 2px var(--nf-primary)`; el porcentaje de debajo pasa a `var(--nf-text)` |
| **Icono de objeto** | igual que el de campeón |
| **Icono de runa** | `transform: scale(1.12)` y `filter: brightness(1.25)` |
| **Icono de habilidad** (`Q › W › E`) | `transform: scale(1.08)` y anillo `--nf-primary` |
| **Fila de especialista** | `background: var(--nf-surface-2)`, `border-radius: var(--nf-radius)`, y el relleno de la barra a `filter: brightness(1.15)` |
| **Tira de cifras de la cabecera** | cada celda: `background: var(--nf-surface-2)` |
| **`‹ Tierlist del grupo`** | `color: var(--nf-primary)` y subrayado |

Tres reglas que van con esto:

- **Ningún dato aparece o desaparece con el hover.** Es exclusivamente acabado, así que en táctil no
  se pierde absolutamente nada. (Es también la regla del proyecto: nada esencial detrás del puntero.)
- Todo lo que tenga hover y sea pulsable de verdad lleva **el mismo tratamiento en `:focus-visible`**,
  con `outline: 2px solid var(--nf-focus)` y `outline-offset: 2px`.
- Y otra vez:
  ```scss
  @media (prefers-reduced-motion: reduce) {
    .cf-card, .cf-icon { transition: none; transform: none; }
  }
  ```

## Obligatorio

- Colores **solo** desde `var(--nf-*)`, espaciados **solo** desde `var(--sp-*)`, tamaños de letra
  **solo** desde `var(--fs-*)`. El `rgba(255,255,255,…)` de las burbujas es la **única** excepción, y
  lo es porque es un brillo sobre el relleno, no un color de la paleta.
- **No hay que crear ningún token.** Los que hacen falta existen en las dos skins: `--nf-void`,
  `--nf-surface`, `--nf-surface-2`, `--nf-surface-3`, `--nf-border`, `--nf-border-strong`,
  `--nf-text`, `--nf-text-mid`, `--nf-text-dim`, `--nf-success`, `--nf-danger`, `--nf-primary`,
  `--nf-focus`, `--nf-gold`, `--nf-shadow-pop`, `--nf-dur-fast`, `--nf-ease-out`, `--nf-radius`,
  `--nf-radius-sm`, `--nf-radius-lg`.
- **Cero emojis.** `npm run arch` los cuenta (`emoji-free`). Si hace falta un icono, **SVG inline con
  `currentColor`**.
- `ChangeDetectionStrategy.OnPush` y `templateUrl`, como ya está.
- `nf-avatar` para los especialistas. Ya no hacen falta `NfSegmented` ni `NfCombobox` en esta vista:
  **quita sus imports** si no queda ningún uso, o TypeScript avisará de importaciones sin usar.

### Que no se cierre la puerta al móvil

- Nada de anchos fijos: la rejilla es `minmax(0, 1fr)` y las tarjetas son fluidas.
- La tira de seis objetos y la de runas van dentro de un contenedor con `overflow-x: auto`.
  El cuerpo de la página no hace scroll horizontal nunca.
- Nada que dependa de `hover`, como ya dice §4.
- Áreas táctiles de `$touch` (44px) en lo interactivo.
- **A 760px el shell cambia el DOM por `matchMedia`**: comprueba la página a 759px.

### Los dos temas

`nocturne` (por defecto) y `original` (`src/styles/themes/original.css`), las dos oscuras y las dos
con `--nf-void` de fondo de página. Comprueba las dos (Ajustes → tema), y en particular: el
desvanecido de la cabecera, las burbujas blancas sobre el relleno verde, y el
`border-color: var(--nf-border-strong)` del hover, que en una skin puede quedarse invisible.
